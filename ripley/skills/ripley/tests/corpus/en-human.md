My first year writing docs I turned in a page about a caching layer that used the
word "leverage" four times. My editor sent it back with one note: say what it does.

It stores the last thousand answers so the database doesn't get asked twice. Nine
words. That was the whole page, and it shipped that afternoon.

I have been trying to work out since then why the long version felt safer to write.
The honest answer is that I did not fully understand the cache, and the vague words
covered the gap. "Leverages an intelligent caching strategy" is a sentence you can
write about a system you have never read the source of. "Stores the last thousand
answers" is not. You have to know the number.

So the plain version is harder, and that is the whole argument for it. Every place
the prose goes vague is a place the writer stopped knowing. Cutting the fog does not
just improve the page — it tells you which parts of the system you still owe an
afternoon to.

I do not think this generalises to poetry. It generalises to everything else I write.
